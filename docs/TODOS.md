## Deferred Features (按优先级排序)

### P1: 用户画像匹配问卷
- **What**: 首次打开时3个问题（身份/每周可用时间/启动资金），案例按匹配度排序
- **Why**: 从"编辑推荐"到"为你推荐"的关键一步，所有用户看相同内容无法最大化留存
- **Pros**: 每个用户看到不同排序，留存率显著提升；为后续个性化推荐打基础
- **Cons**: 需要额外的UserProfile数据模型；AI匹配算法需要设计
- **Context**: 用户验证已通过（10人强正面反馈），但当前所有用户看完全相同的Top3。解锁条件：留存数据证明用户有回访习惯（D1留存>30%）
- **Effort**: S（CC ~15min） | **Priority**: P1
- **Depends on**: MVP上线 + 7天留存数据

### P1: "经典回顾"标签
- **What**: 重复推荐的高分案例标注"经典回顾 | 首发于YYYY-MM-DD"
- **Why**: 兜底机制用户侧闭环，没有它用户发现重复内容会觉得产品没更新
- **Pros**: 透明不欺骗，增加信任感；实现极简（is_classic字段+UI标签）
- **Cons**: 无
- **Context**: 兜底机制已在设计（is_classic字段），但用户侧展示延后。解锁条件：出现首次重复推荐时（约第34天后，100篇初始库用完时）
- **Effort**: S（CC ~5min） | **Priority**: P1
- **Depends on**: 出现首次重复推荐

### P2: 阅读进度 + 已读/未读标记
- **What**: 案例详情页显示阅读进度，完成后标记已读。首页卡片显示已读/未读状态。
- **Why**: 用户完成感驱动回访，"已读2篇还剩1篇"给用户回来的理由
- **Pros**: 低成本增加回访动力
- **Cons**: 需要UserRead集合；增加首页查询复杂度
- **Context**: 解锁条件：用户日均打开>1次（说明有回访习惯，值得优化体验）
- **Effort**: S（CC ~15min） | **Priority**: P2
- **Depends on**: MVP上线 + 日均打开频次数据

### P2: "我在做"状态标签
- **What**: 收藏按钮旁加"我在做"按钮，个人中心区分"想做的"和"正在做的"
- **Why**: 从"读者"到"行动者"的转折点，个人中心变成项目面板
- **Pros**: 用户从被动阅读变为主动执行；可追踪"行动转化率"
- **Cons**: UserCollection增加status字段（collected/doing/done）；UI需新增状态切换
- **Context**: 解锁条件：Checklist使用率>30%（说明用户真的在用步骤追踪功能）
- **Effort**: S（CC ~15min） | **Priority**: P2
- **Depends on**: Checklist使用率数据

### P2: 埋点分析仪表盘
- **What**: 管理后台页面（管理员可见），显示日活/留存/点击率/收藏率实时图表
- **Why**: 试运营用查询脚本替代，但长期需要可视化
- **Pros**: 数据驱动决策的效率10x；内部创业展示的核心论据
- **Cons**: 需要AdminDashboard页面 + 云函数聚合查询 + 图表库
- **Context**: 解锁条件：试运营结束后。试运营期间用NoSQL查询脚本生成日报
- **Effort**: M（CC ~30min） | **Priority**: P2
- **Depends on**: 试运营结束 + 指标确认

## Known Gaps

### GAP-1: 内容脱敏正则不完美
- **What**: LLM评分管道中的正则脱敏可能漏过部分敏感信息模式
- **Impact**: 用户可能看到原文中的微信号/电话号码
- **Mitigation**: 人工审核时二次检查；用户投诉入口
- **Priority**: 持续改进

### GAP-2: 定时精选任务失败兜底
- **What**: 云函数定时触发器执行失败时，首页无数据
- **Impact**: 用户打开首页看到空内容
- **Mitigation**: getDailyPick查询失败时回退到最近有效日 + SystemLog记录执行状态
- **Priority**: P1（开发时实现）

### GAP-3: 微信订阅消息 API 限频策略
- **What**: subscribeMessage.send API 有调用频率限制，批量发送 300+ 条可能被限频
- **Impact**: 部分用户收不到推送通知
- **Mitigation**: 当前实现：每条间隔 200ms。需进一步确认微信官方限频阈值，可能需要分批发送（如每批 50 条，批次间间隔 1 秒）
- **Priority**: P1（推送功能开发前确认）
